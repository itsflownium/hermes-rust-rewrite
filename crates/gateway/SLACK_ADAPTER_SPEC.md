# Slack stock plugin implementation spec

Slack is the third stock messaging plugin, after Discord and Telegram. Local implementation and conformance can proceed while Telegram live acceptance is pending. Release integration follows the shared gateway and earlier messenger gates. The reference is the bundled Slack platform in Hermes v0.23.4 and Slack's current Agent messaging experience. An operator can run a Slack app from a headless Mercury profile, work in multiple authorized Slack workspaces, and resume the same sessions and delivery receipts after a restart. [Shared gateway contract](ADAPTER_CONTRACT.md) · [Telegram spec](TELEGRAM_ADAPTER_SPEC.md) · [Hermes Slack guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md) · [Next adapter, WhatsApp linked-device](WHATSAPP_ADAPTER_SPEC.md#linked-device-adapter)

## Target architecture and setup

Register the [`hermes-slack-plugin` crate](../plugins/slack/) as a stock factory with platform key `slack`. Use the existing Rust HTTP and WebSocket clients for the Slack Web API and Socket Mode. The Slack crate owns its manifest, credential verification, wire events, Slack permission evidence, message rendering, and platform effect evidence. The profile owner supplies shared configuration, leases, native command and session authority, intake, and the delivery outbox. [Mercury adapter interface](src/messaging/types.rs) · [Hermes Slack manifest](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/slack/plugin.yaml) · [Slack Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/)

- Configure one verified Slack app receiver with an app-level secret reference and one or more verified bot installation records. Each installation records the app, workspace or enterprise installation context, bot identity and credential reference. Verify the bot token through `auth.test` and check its app association against Slack's bot or installation metadata. An installation uses its own Web API client for reads and writes. The profile owner holds an app receiver lease and an account lease for each verified installation it activates. Rotate a secret in place for the same verified identity. Hold a changed or invalid installation for private owner review and preserve its original receipts. [Slack auth.test](https://docs.slack.dev/reference/methods/auth.test/) · [Slack bots.info](https://docs.slack.dev/reference/methods/bots.info/) · [Hermes multi-workspace setup](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#multi-workspace-support)
- Generate an Agent-view app manifest from the native command catalog and the enabled capabilities. Enable Socket Mode with the app token's `connections:write` scope and validate the applicable bot scopes. Subscribe to direct, group direct, public and private channel message events, mentions, current Agent-view context and stop events, and opt-in file or reaction events. The private setup surface verifies the app and reports missing scopes, uninstalled workspaces or inaccessible conversations. The operator installs or updates the manifest in Slack. [Hermes manifest setup](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#option-a-from-a-hermes-generated-manifest-recommended) · [Slack Agent migration](https://docs.slack.dev/changelog/2026/08/20/agent-updates/)
- Bind every event to a verified installation using the socket's verified app identity and Slack's installation evidence. In Slack Connect, check the installed team separately from the sender's home team and the channel's origin. If install metadata is insufficient, resolve it only from verified evidence for the same app and channel. Report an ambiguous installation as a refusal. Workspace, conversation, and user labels are display metadata. [Slack Events API](https://docs.slack.dev/apis/events-api/#callback-field-overview) · [Hermes workspace resolution](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/slack/adapter.py#L3548)

## Authorization, routes, and context

Apply user, channel, and command grants to the verified installation. Support authorized DMs, opt-in DM pairing, MPIMs, and permitted public and private channels. A one-to-one DM can use its own access rule. An MPIM uses the group rule. Mention-free or continued-thread behavior still requires the current conversation and actor grant. Revalidate conversation access before Slack API reads or sends and revoke scoped work when a workspace is uninstalled or a user loses access. [Hermes Slack channel filtering](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#channel-allowlist-allowed_channels) · [Slack Conversations API](https://docs.slack.dev/apis/web-api/using-the-conversations-api/)

- In channels, an addressed top-level message normally opens a thread reply under its message timestamp. An existing thread keeps its own root `thread_ts`. Flat replies and shared channels are explicit policy choices. DMs support thread-separated sessions and a shared DM conversation. Preserve the exact outbound destination independently of the session binding. Slack message timestamps are opaque strings. Scope all keys, context watermarks and receipts by verified installation, channel, and thread, plus participant where policy isolates users. [Hermes Slack thread routing](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/slack/adapter.py#L4360)
- Support mention and reply triggers, strict thread mention rules, opted-in free-response rooms, and authorized continuation after the bot joins a thread. Use verified bot identity to suppress self-echo. Peer bot handoffs are opt-in and the mention mode requires a fresh mention in each peer event. Treat a post made through a user token as human only where authenticated Slack facts and that user's explicit grant support it. Configured reaction triggers may start a turn only for a currently allowed reactor. If the trigger routes elsewhere, authorize both the source context and the new audience before creating the intent. [Hermes Slack trigger policy](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#mention--trigger-behavior) · [Hermes peer bot behavior](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#accepting-messages-from-other-bots-allow_bots) · [Hermes reaction triggers](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#reaction-triggers-reaction_triggers)
- Apply channel and thread model, prompt, skill, tool and approval overrides at native claim. Provide bounded authorized thread context at first engagement and a delta after restart or a new explicit mention. Keep a per-binding watermark and stage the root's authorized media through the same file boundary. A Slack Agent-view context event can label the channel the user is viewing. A context label itself grants no history or file access. Context enrichment keeps the original command text and prior transcript intact. [Hermes thread context](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/slack/adapter.py#L4392) · [Hermes Agent messaging experience](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#agent-messaging-experience)

## Socket Mode, intake, and recovery

Open a temporary Socket Mode URL with `apps.connections.open` only while holding the app receiver lease. Verify the app in the handshake and route each accepted envelope through its scoped account generation. Track ping/pong, hello, reconnect, and receive progress separately from Web API success. Drain and hand off planned reconnects under the same lease. Stale sockets cannot admit work or issue callbacks for a new generation. [Slack connection API](https://docs.slack.dev/reference/methods/apps.connections.open/) · [Hermes Slack socket lifecycle](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/slack/adapter_socket_lifecycle.py)

Commit a disposition within the Socket Mode acknowledgement budget using a bounded lane ahead of model work, media downloads, history reads and outbox effects. Acknowledge the current `envelope_id` only after the durable intake, duplicate or refusal receipt exists. Use Slack Events API `event_id` as a transport replay identity. Derive the logical message key from the verified installation, conversation and exact message `ts` so `message`, `app_mention`, and a file-share event representing the same post converge on one native admission. Persist occurrence-specific identities for edits, commands, actions and reactions. Record file-share metadata under the source logical input. Recheck permission and action scope before applying an edit or control. [Slack Socket Mode acknowledgements](https://docs.slack.dev/apis/events-api/using-socket-mode/#acknowledge-events) · [Slack Events API delivery and retries](https://docs.slack.dev/apis/events-api/#retries)

Treat reconnect and unacknowledged retries as at-least-once delivery. Reopen the same host receipts and record an observed gap when Slack's retry window or transport evidence leaves missing events. Use the authorized thread context path to rehydrate available messages on the next turn. A hydration read is contextual and does not submit historical messages for execution. Observe Slack's workspace and method-specific limits for history and reply reads. [Slack conversations.replies](https://docs.slack.dev/reference/methods/conversations.replies/) · [Hermes Slack context fixture](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tests/gateway/test_slack_thread_watermark_off_loop.py)

## Commands and interactive controls

Expose native Slack slash commands and the supported `!command` thread form from the same native catalog. Keep slash results ephemeral and use the invoked thread for thread-command replies. Support help and status, native session and queue controls, direct and interactive model selection, approvals, clarification, scoped skill commands, and proactive target setup. Use Block Kit action controls bound to the exact actor or operator, installation, channel, thread, originated message, native request and generation. An approved actor can answer by button or a scoped text reply. Edit or retire the original card when the native decision settles, expires or is cancelled. [Hermes Slack slash commands](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#slash-commands) · [Slack Block Kit actions](https://docs.slack.dev/reference/interaction-payloads/block_actions-payload)

Use durable receipts to acknowledge slash and interactive envelopes within Slack's three-second deadline. Send an eligible private response through the permitted acknowledgement payload or an expiring scoped response handle. Protect `response_url` as a credential, honor Slack's response window and count, and keep a private result inside that audience on retry or expiry. A message typed with `!command` follows the authorized visible conversation route. Direct approvals, clarification, and a subscribed Agent stop event use the same native authority as local clients. Match a stop to the active authorized execution and its bound Slack stream or Agent session before interrupting. Replayed clicks and stop events read a prior decision or return stale. [Slack interaction deadlines](https://docs.slack.dev/interactivity/handling-user-interaction/#acknowledgment-response) · [Slack Agent stop event](https://docs.slack.dev/reference/events/agent_session_stopped/)

## Outbound delivery, streaming, and media

**Messages and notifications.** Prepare `mrkdwn` or opt-in Block Kit with accessible fallback text, bounded tables and splits, explicit mention policy, and configured link and media unfurls. A thread reply uses the confirmed root timestamp. A configured thread broadcast requires authorization to the parent channel audience and is recorded as an effect extending the thread reply's visibility. Use the workspace-scoped client for every part, reaction and message edit. Verify home, channel, thread or member DM targets before use by the scheduler, signed webhooks, background sessions and authorized manual sends. Resolve a member to a DM through `conversations.open` under the approved installation. [Slack chat.postMessage](https://docs.slack.dev/reference/methods/chat.postMessage/) · [Slack conversations.open](https://docs.slack.dev/reference/methods/conversations.open/) · [Hermes Slack delivery targets](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/plugins/platforms/slack/send_targets.py)

**Agent Sessions and native streams.** Use current Agent Sessions status and naming where enabled. Use `chat.startStream`, `chat.appendStream` and `chat.stopStream` on eligible routes, with the verified recipient and team when Slack requires them. Keep the returned stream message timestamp and each confirmed append revision in the outbox. Support native task cards for tool progress and opt-in Block Kit feedback buttons on eligible final replies. Enforce Slack's stream limits across calls, including the 12,000-character text budget and ten-minute duration. End or roll the stream under the same destination order when a limit is reached. Publish the committed final reply through the stream or its confirmed message when eligible. When a route supports ordinary final messages only, use the ordered text plan. A lost append or stop acknowledgement requires exact evidence or owner resolution before retrying that effect or sending an alternative. [Slack streaming API](https://docs.slack.dev/reference/methods/chat.startStream/) · [Slack Agent Sessions](https://docs.slack.dev/ai/agent-sessions/) · [Hermes native streaming and task cards](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#native-streaming-live-typing-replies)

**File and voice workflows.** Authorize Slack file metadata and private downloads through the installation that received the source message. Resolve Slack Connect file stubs before staging and keep download credentials scoped to the trusted Slack origin. Support images, files, video and audio through private host artifacts. Transcribe authorized voice notes and upload generated speech as an audio attachment. For an outbound file, persist the file ID from `files.getUploadURLExternal`, transfer the staged bytes, then run the approved `files.completeUploadExternal` share for the exact channel or thread. The transfer receipt and the visible share receipt are distinct. Slack permits one completion per allocation. A known aborted preparation can expire unshared. An unknown share blocks that destination until its exact file/share evidence or an owner decision settles it. [Slack file allocation and transfer](https://docs.slack.dev/reference/methods/files.getUploadURLExternal/) · [Slack file sharing completion](https://docs.slack.dev/reference/methods/files.completeUploadExternal/) · [Hermes Slack voice](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/messaging/slack.md#voice-messages)

**Rate limits and recovery.** Use confirmed Slack outcomes, including `ok:false` classifications, and persist a 429 `Retry-After` in the applicable workspace, API-method or narrower destination domain. Slack's workspace method quota and channel posting limit can both govern one effect. Keep other work eligible where the cooldown permits. Reconcile against exact app, installation, destination and message or file identity. A time or text match yields no delivery confirmation. Preserve the state of each step when the receiver reconnects or the gateway restarts. [Slack Web API rate limits](https://docs.slack.dev/apis/web-api/rate-limits/)

## Local implementation

Create one `slack` profile entry per installed workspace. Set `app_id`, `team_id` and `bot_id` for each entry. Set `receiver_owner` on one entry for the app. Enroll each installation through the private profile owner with its `bot_token`. Include the `app_token` in the receiver owner's enrollment. The verification status exposes the generated manifest and the installation and socket state. Scope access with the gateway account, room and thread rules. [Stock adapter settings](../plugins/slack/src/settings.rs)

- The optional `home_member` resolves a workspace member to a verified direct destination and exposes its route ID in verification status. An explicit `home` takes an existing room. Each entry can configure one of these options.
- A `peer_bots` entry names the Slack bot ID and selects `mention` or `always`. The account and room policy must also grant its bot user access. Peer posts enter as shared actors.
- A `reaction_triggers` entry names an emoji and supplies a source room, a destination room and a prompt. Grant the actor and destination under `access.scope.events.slack-reaction` with a resource key of the form `channel/emoji`. Mercury checks both audiences. A cross-room trigger uses the configured prompt while the reacted message stays in its original audience.
- Channels in `broadcast_channels` require the parent room and thread notification grants before sharing a reply to the channel. Opt-in direct pairing uses `/mercury-pair` and private profile owner approval.

The fixture suite exercises shared receiver leases, workspace and Slack Connect routing, retries across restart, private slash callbacks, scoped controls and feedback, native stream completion and stop, thread root media, resumable outbound uploads, and scheduled, webhook and background replies. Remaining acceptance work covers expanding the native slash catalog, Agent session naming, live tool progress cards and additional Slack audio formats. Live acceptance also verifies the provider behavior in the table above. [Slack conformance fixtures](../plugins/slack/tests/conformance.rs)
